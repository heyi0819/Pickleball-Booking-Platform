## 真實 runtime observation

1. Canonical LIFF 初次載入顯示「無法完成 LINE 登入，請稍後重試。」與可操作的「重試」。按重試後成功進入角色選擇，並進入 STUDENT 首頁。未取得初次失敗的精確原因，不能歸因為 Render cold start 或認定為登入 defect。
2. 既有帳號可選 STUDENT、COACH、COMMITTEE。本人 profile 成功呈現；不在 evidence 複製姓名、email、OAuth callback code 或 token。
3. STUDENT `/demand` 分開顯示公開招生及 availability selection。載入完成後可選一筆核准時段。沒有公開招生與本人需求紀錄；尚未建立／送出需求或報名。
4. COACH `/availability` 顯示同一核准時段為「已通過」；沒有邀請。`/courses` 呈現授課 empty state。沒有編輯既有時段入口。
5. 實際觀察到 `/availability` 尚在取得資料時先顯示「尚未建立可授課時段」，之後換成一筆已通過時段。此為 loading 與 empty 混淆的已觀察 UI 問題；已完成最小前端修復，尚未部署到 pilot。
6. Admin 初次顯示管理後台登入頁，LINE 按鈕可到達 LINE 既有帳號確認頁。自動核准審查拒絕代理代按最終登入；等待 maintainer 在 UI 完成登入。未宣稱 Admin authentication PASS。
7. 要求 viewport 390×844 時，工具回報實際 DOM viewport 379×632、document scrollWidth 364。已檢視窄版 demand screenshot：無水平溢出，底部四個導覽可見；不能宣稱已精確覆蓋 390×844 或實體鍵盤／LINE WebView。
