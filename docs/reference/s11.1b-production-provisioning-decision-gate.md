# S11.1B Production Provisioning Decision Gate

## Status and boundary

S11.1B records the repository-only **future paid production upgrade profile** on the S11.1A foundation at `0b4eeec8d3710faba95b9368c54942ebd8c79db1`. It is not the current active runtime strategy. The active test/pilot target is the zero-cost Cloudflare Pages Free + Render Free + Neon Free path documented in `s11-zero-cost-runtime-architecture-correction.md`.

GCP provisioning is deferred. S11.1C is `BLOCKED / DEFERRED` unless a maintainer explicitly approves a paid-production activation after the zero-cost hard gates or upgrade triggers are met. This slice does not provision a GCP, Cloudflare, LINE, billing, GCS, Secret Manager, Cloud SQL, or Cloud Run resource; it does not run a live Terraform plan or apply; and it does not modify staging.

`infra/terraform/environments/production/terraform.tfvars.example` is a non-secret configuration example. It is not a usable production configuration and retains all real project, bucket, domain, image, and LINE values as placeholders.

## Approved future paid-production reference profile

| Area | Approved initial value | Boundary / follow-up trigger |
| --- | --- | --- |
| Runtime region | `asia-east1` | `asia-southeast1` is fallback only when provisioning evidence requires it. |
| Cloud SQL | PostgreSQL 18, `ENTERPRISE`, `db-custom-1-3840`, 20 GiB `PD_SSD` | Do not change to Enterprise Plus, 2 vCPU / 16 GiB, or 100 GiB without new maintainer authorization. |
| Availability | `ZONAL` | Upgrade to `REGIONAL` only after approved availability/cost evidence: a production incident, measured RTO risk, or a revised availability target that ZONAL cannot meet. |
| Storage and protection | autosize enabled; PITR enabled; deletion protection enabled | Storage can grow automatically. A later decrease is not an assumed rollback path. |
| PITR logs | 7 days | This is the Cloud SQL Enterprise maximum represented by this root. |
| Automated backups | 14 retained | Independent from logical backup retention. |
| Cloud Run API | 1 CPU, 1 GiB, min 1, max 3, concurrency 40, timeout 60 seconds | Do not increase max instances for theoretical HA. Change capacity only with production evidence. |
| Logical backup | daily, 35 days, age-encrypted, separate backup project | The final backup implementation and restore rehearsal are owned by S11.4. |
| Encryption | Google-managed encryption at rest for Cloud SQL/GCS; age for logical backups | CMEK is not required for MVP production. |
| Recovery objectives | RPO <= 15 minutes; RTO <= 4 hours | Targets only. S11.4 must prove them by restore rehearsal. |

Enterprise is selected instead of Enterprise Plus to keep the initial MVP Cloud SQL profile within the approved one-vCPU / 3.75 GiB cost envelope. ZONAL is an accepted initial availability trade-off, not a claim of regional high availability. PITR and deletion protection protect recoverability, but do not replace a REGIONAL availability design when the approved objective changes.

Cloud Run min instances is `1` to avoid routine scale-to-zero startup latency for the initial API. Max instances is `3` to cap the initial connection/cost envelope around the small ZONAL database. Sustained saturation, database connection pressure, request latency, or an approved availability target are the required evidence for a later capacity review.

Seven-day PITR supports short-window point-in-time recovery. It is deliberately separate from the 14 retained Cloud SQL automated backups and the 35-day age-encrypted logical backup retention. There is no current legal or compliance requirement for 90-day retention.

## Explicit Terraform encoding

The Google provider lock is `hashicorp/google` 7.46.0. `google_sql_database_instance.settings.edition` explicitly encodes `ENTERPRISE` so a PostgreSQL 18 provider default cannot silently select Enterprise Plus. The root also sets:

```hcl
backup_configuration {
  point_in_time_recovery_enabled = true
  transaction_log_retention_days = var.database_retained_transaction_log_days
}
```

`database_retained_transaction_log_days` is a number validated from 1 through 7, which is the supported Cloud SQL PostgreSQL Enterprise range. The approved example value is `7`. This value is configuration only: it contains no database credential, secret version, or secret payload.

## Custodian and state governance

The initial production model is a **solo maintainer**. This document does not claim dual control. Required compensating controls are MFA for Google/GCP, GitHub, and the LINE Console; GitHub OIDC/WIF rather than long-lived service-account JSON keys; a separate break-glass identity where practical; offline/separate storage of the age private identity; explicit production deployment authorization; Git/CI evidence for production infrastructure changes; periodic IAM review; no repository secrets; and no developer-local Terraform state as the source of truth.

State uses a versioned GCS backend in a distinct production infrastructure/state project. The initial custodian administers state. The GitHub release identity has no state administration; runtime and migration identities have no state access. Actual project IDs and bucket creation are reserved for S11.1C.

## Domains and LINE isolation

LIFF and Admin use custom production domains, while the API initially remains on a Cloud Run `*.run.app` URL. The production apex domain is intentionally open and must be supplied before S11.2 configures production LINE or Cloudflare. This does not block S11.1B repository closure.

Production uses separate LINE Login channel, LIFF app, and Messaging credential/channel as required. No staging LINE identifier or secret may be reused. Actual IDs and secrets are created outside this slice in S11.2.

## Open inputs and provisioning boundary

The following are intentionally not invented or stored here:

- runtime, infrastructure/state, and backup GCP project IDs;
- state and backup bucket names/locations;
- production apex domain;
- LINE production IDs and all LINE secrets;
- runtime image digest and all secret payloads;
- final logical-backup implementation; and
- production resource billing account.

After explicit S11.1B merge authorization and main CI closure, this profile remains a validated Terraform reference only. It does not start S11.1C or S11.2. S11.1C may be reconsidered only after an explicit paid-production architecture/cost approval; until then it is `DEFERRED`.
