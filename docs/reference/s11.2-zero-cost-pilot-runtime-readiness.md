## Known free-tier operating constraints

- Render remains a single-instance Free service. Cold wake-up after idle is expected; no persistent disk, worker, cron/job, autoscaling, or speculative JVM tuning is approved.
- Neon remains Free. Normal application traffic uses its approved pooled route; migration, `pg_dump`, and restore use a direct non-pooler route with TLS. No plan upgrade is allowed.
- Cloudflare Pages remains static and Free. No Pages Functions or custom domain is required.
- The current documented UptimeRobot Free monitor covers the public Render health endpoint every five minutes. It does **not** establish LIFF or Admin monitor coverage.

## Required maintainer manual evidence before sealing

Repository/public probes cannot read provider dashboards or perform a real LINE sign-in without an authorized maintainer session. Record only pass/fail and non-sensitive evidence; never record credentials, tokens, subjects, or connection strings.

1. **Cloudflare Pages:** confirm both projects use production branch `main`, their current build environments retain the two public values (`VITE_API_BASE_URL` to the Render `/api/v1` base and the staging `VITE_LIFF_ID`), no Pages Functions dependency exists, and the canonical URLs serve the intended main artifact.
2. **Render:** confirm the service is Free, Java 21 Docker, has no disk/worker/cron/autoscaling, the latest compatible deployment is live, runtime Flyway and workers remain disabled, the exact CORS origins are the two canonical Pages URLs, and memory/quota evidence shows no pressure. Do not add JVM tuning without that evidence.
3. **Neon:** confirm the `pickleball-stg` Free project/database remains reachable over TLS; record current storage, compute, and public-egress consumption; verify V13 is the highest successful Flyway version; and verify `pickleball_app` has runtime DML only while `pickleball_migrator` owns migration DDL. No destructive data operation or plan upgrade is authorized.
4. **LINE:** in the LINE Developers Console, confirm the existing staging LIFF endpoint and the Admin callback `https://pickleball-stg-admin.pages.dev/auth/line/callback`. Repeat a real mobile LIFF launch through `/me`, then a real Admin LINE Login through the privileged-role gate. Confirm logout/re-login works and neither flow exposes a provider token or subject in the visible URL or logs.
5. **Monitoring and cold start:** record whether free monitors exist for LIFF and Admin; they are currently undocumented/missing. Because the API health monitor runs every five minutes, an idle-spin-down test cannot be induced without changing monitoring. A maintainer may perform one controlled acceptance window and classify the first request after idle as PASS, PASS WITH EXPECTED FREE-TIER DELAY, or FAIL; do not disable monitoring or add a paid monitor for this slice.
6. **Backup:** record the latest encrypted logical-backup metadata and a non-destructive restore-rehearsal result, if one exists. The age private identity and archive location remain outside Git.
