# S10.4 Real LINE / LIFF Acceptance

S10.4 enables the existing staging LIFF frontend to use a separately owned, non-production LINE Login channel. It adds no product capability, Flyway migration, paid resource, production resource, Messaging API channel, webhook, or worker.

## Scope and boundary

| Component | Non-sensitive identifier | Boundary |
| --- | --- | --- |
| LINE provider | `pickleball-stg` | Separate staging-only provider |
| LINE Login channel | `pickleball-stg` (`2011349413`) | Published; no Messaging API resource |
| LIFF app | `pickleball-stg-liff` (`2011349413-coxfchhN`) | Full-size endpoint at `https://pickleball-stg-liff.pages.dev` |
| Render API | `pickleball-stg-api` | Free staging service |
| Cloudflare Pages LIFF | `pickleball-stg-liff.pages.dev` | Free staging Pages project |

The provider and channel are deliberately separate from the legacy LINE resources. The LIFF app has only the `openid` and `profile` scopes, has `chat_message.write` disabled, and has add-friend disabled.

## Real-device acceptance

The maintainer accepted the staging LINE consent flow and launched the LIFF app in a mobile LINE/browser context. The representative result was a successful LIFF launch at the canonical Pages URL, with authenticated STUDENT entry and the existing member/profile page rendered. The accompanying mobile evidence is intentionally not committed because it can contain personal UI context.

For a repeat acceptance, launch:

```text
https://liff.line.me/2011349413-coxfchhN
```

Then verify that the LIFF app returns to `pickleball-stg-liff.pages.dev`, exchanges the LINE ID token successfully, and loads the authenticated current-user state. Report only success/failure and any non-sensitive error text; do not send an ID token, platform JWT, LINE user ID, password, MFA value, Channel Secret, or access token.

## Deferred frontend polish

The real-device screen confirms the architecture and authentication path, but the current sealed frontend still includes English labels and uses a basic mobile layout. Full Traditional Chinese localization and responsive visual refinement are a follow-up frontend scope; they are intentionally not mixed into this auth acceptance slice.

## Rollback and forward-fix

- To disable this staging login path, first remove `VITE_LIFF_ID` from the Pages build configuration and redeploy, then remove `LINE_LOGIN_CHANNEL_ID` from Render and redeploy.
- To revoke compromised LINE credentials, use the owning LINE Developers Console and update the single staging consumer; do not place replacement values in Git.
- Database changes remain forward-only. S10.4 introduces none.
- Do not alter the published staging channel's scopes, add a Messaging API resource, enable a webhook, or alter production resources as part of this slice.
